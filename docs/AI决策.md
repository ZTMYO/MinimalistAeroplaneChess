# AI 决策流程逻辑文档

本文档描述《极简飞行棋》中 AI 玩家（Bot）及 AI 托管模式下的决策逻辑。

## 1. 核心架构

决策本身是一份**纯函数**：[shared/bot.mjs](file:///d:/zc/极简飞行棋/shared/bot.mjs) 的 `chooseAction(state, player, { difficulty })`。它只读引擎状态，返回一个待执行的动作，前端与服务端共用同一份，因此单机和联机的 AI 走法完全一致。

出手的驱动方式分两种：

- **单机 / 本地多人**：由前端 [botController.js](file:///d:/zc/极简飞行棋/frontend/js/botController.js) 驱动。先停 200ms - 300ms 像在思考，再照动作走客户端既有的点击路径（掷骰 / 选子 / 用道具 / 传送），复用同一套动画与音效；出手后留 300ms 余量解锁，避免同一回合被连点。
- **联机**：由服务端 [botDriver.cjs](file:///d:/zc/极简飞行棋/backend/botDriver.cjs) 驱动。服务端算出动作并裁决，再广播快照；节奏看各端回执——客户端把这一帧演完才出下一手，没人回执时退回估时表。开局第一手会等 1500ms，让各端铺好牌桌。

两种驱动都不碰规则：规则全在 [engine.mjs](file:///d:/zc/极简飞行棋/shared/engine.mjs)，AI 只负责「选哪个动作」。

## 2. 难度等级

难度只影响两件事：

- **简单 (Easy)**：不购买道具，选子时在可动棋子里随机挑一颗。
- **困难 (Hard)**：会购买道具，并用评分系统挑最优的棋子和点数。

## 3. 掷骰子阶段决策

轮到 AI 掷骰时，`chooseAction` 的流程：

1. **前置检查**：游戏未结束、当前轮到该玩家。
2. **道具评估**（仅困难难度，且处于 `rolling` 阶段、尚无待落地道具）：按固定优先级择一购买，见下表。买了占用回合的道具（遥控骰子、传送门）后，这一步不再普通掷骰。
3. **道具落地**：若已买下遥控骰子/传送门，这一步替它选点或选子（人类买了道具被托管时同样适用，所以不看难度）。
4. **执行掷骰**：没有使用道具则普通掷骰。

## 4. 道具使用策略（困难模式）

道具触发都是**确定性条件**，不含概率。购买优先级：遥控骰子 → 传送门 → 盲盒 → 多面骰子。

| 道具 | 消耗 | 触发条件 |
| :--- | :--- | :--- |
| **遥控骰子** | 70 | 遍历 1-6 点，存在某个点数的最佳走法评分 ≥ 500（即能击败），且积分足够。 |
| **传送门** | 40 | 处于落后状态（与最领先者的进度差 ≥ 25）且轨道上有己方棋子，且有合法空位落点。 |
| **盲盒** | 15 | 严重落后（进度差 ≥ 60），且积分 ≥ 15 但不足 40（40 以上被盲盒自身规则拦下）。 |
| **多面骰子** | 50 | 处于落后状态且轨道上有己方棋子，且积分足够。 |

落后判据基于「各棋子完成度之和」：4 子局满分 400。

## 5. 棋子选择策略（困难模式评分系统）

掷出点数后，对每个可动棋子跑一次引擎 `preview`，按事件流加分：

| 后果类型 | 评分 | 说明 |
| :--- | :--- | :--- |
| **直接获胜** | +2000 | 这一步送完最后一块棋子。 |
| **到达终点** | +450 | 送一块进终点（未能直接获胜时），略低于击败。 |
| **击败对手** | +500 | 另按被击败棋子的进度额外 +3/点，越接近终点越值。 |
| **欢乐模式碰撞** | +550 | 踩敌人换步数，另按敌人数 +100/颗、奖励步数 +15/步。 |
| **叠子反弹后击败** | +400 | 通过反弹产生的击败。 |
| **跳跃 / 飞棋** | +300 | 快速推进（飞棋在事件流里也是 jump）。 |
| **起飞** | +200 | 基地棋子出门。 |
| **普通移动** | +50 | 基础移动分。 |
| **反弹** | +20 | 未产生击败的普通反弹。 |
| **撞叠子** | -200 | 正常模式下双方都回家，需规避。 |

同分时取走得最远的一步。

### 特殊取舍
- **进终点 vs 击败**：不能直接赢时，到达终点（+450）低于击败（+500），AI 会优先削弱对手。
- **追击高价值目标**：击败的额外分按「被击败棋子的完成度」计算，因此 AI 倾向击杀最接近终点的敌人。

## 6. 执行与反馈
1. **日志**：单机在控制台打印 `[AI]` 系列日志；服务端同样以 `[AI]` 前缀记录出手与拒绝原因。
2. **执行路径**：单机通过 `eventHandler` / `chessPiece` / `skillManager` 的既有处理函数出手，确保与玩家手动点击完全一致，从而触发正常的动画同步和音效；联机则由服务端裁决结果随快照下发。
